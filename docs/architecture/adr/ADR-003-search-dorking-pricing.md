# ADR-003: Применение поискового доркинга по сниппетам для сбора рыночных предложений

* **Статус:** Принято
* **Дата:** 24.11.2026
* **Контекст:** Для построения ценового коридора («Низ — Середина — Верх») и отсева невыгодных предложений системе требуется получать актуальные заголовки и цены товаров с доверенных площадок (DNS, Ситилинк, Ozon, Яндекс Маркет), не нарушая стабильность работы на демонстрации и в автотестах (NFR-006).

## Рассмотренные альтернативы
1. **Прямой скрапинг маркетплейсов через headless-браузеры (Playwright / Selenium):**
   * *Плюсы:* Доступ к полной верстке карточки товара.
   * *Минусы:* Высокая вероятность блокировки по IP и срабатывания антибот-капч (риск R-001); высокое потребление оперативной памяти и CPU в Docker-контейнере; хрупкость парсеров при изменении верстки магазинов.
2. **Предварительный парсинг каталога в локальную БД PostgreSQL:**
   * *Плюсы:* Мгновенный отклик при поиске.
   * *Минусы:* Превращает сервис в статический товарный агрегатор; невозможность масштабирования на произвольные товарные домены; быстрое устаревание цен.
3. **Поисковый доркинг в реальном времени (Search Engine Dorking) + HTTP-кассеты для тестов:**
   * *Плюсы:* Использование поисковых операторов (`site:dns-shop.ru`, `site:ozon.ru`) позволяет получать прямые ссылки, названия конфигураций и индикативные цены из поисковых сниппетов без обхода антифрода магазинов; для детерминированных тестов (КТ-3) ответы записываются в локальные HTTP-кассеты (`vcrpy`).

## Принятое решение
Реализовать сбор рыночных данных через **поисковый доркинг по сниппетам** (библиотека `duckduckgo-search` + `trafilatura` для открытых веток форумов) из эталонной неавторизованной сессии. Для нивелирования динамического ценообразования маркетплейсов (риск R-002) система оперирует ценовым коридором и выводит обязательный дисклеймер.

## Последствия и компромиссы
* **Положительные:** Нулевой риск блокировки по IP на защите; легкий Docker-образ без браузерных движков; 100% воспроизводимость автотестов.
* **Отрицательные:** Поисковые сниппеты не всегда содержат информацию о персональных скидках аккаунта (СПП), что решается переходом к индикативной вилке цен.

**Поисковый доркинг по сниппетам** - это сбор данных о товарах через стандартный поисковик без прямого захода скрипта на сайты магазинов.  
    * *Обход капч и антифрода:* Крупные маркетплейсы блокируют автоматические парсеры, но свободно отдают свои страницы поисковым роботам.  
    * *Легкость системы:* Не нужно запускать тяжелый виртуальный браузер (Playwright/Selenium) внутри Docker-контейнера, что экономит оперативную память.
