# Реестр нефункциональных требований (NFR)

### Базовые условия и стенд тестирования
Все требования проверяются в рамках КТ-3 и КТ-4 на локальном стенде разработчика:
*   **Конфигурация хоста:** AMD Ryzen 7900X (12 ядер), 32 ГБ DDR5 RAM, NVIDIA RTX 4090 (24 ГБ VRAM).
*   **Окружение:** Linux (Ubuntu / WSL2), Docker Compose v2, Ollama.
*   **Эталонный тестовый профиль:** Запрос *«Хочу в подарок купить что-то из флагманов телефонов самуснг»* с зафиксированным набором из 15 страниц форумов и 50 сырых товарных карточек (записанных в HTTP-кассету `vcrpy`).

---

### NFR-001: Локальная автономность инференса ИИ
*   **Суть:** В рамках MVP вычисления языковой модели должны выполняться строго локально без отправки пользовательских запросов во внешние облачные LLM API. На уровне архитектуры закладывается интерфейс адаптера 
для бесшовного перехода на отечественные облачные провайдеры (YandexGPT, GigaChat) и ансамбли моделей в будущих инкрементах.
*   **Метрика / Порог:** Количество обращений к внешним API языковых моделей = 0.
*   **Условия:** Полный цикл обработки эталонного запроса.
*   **Метод проверки:** Аудит сетевых соединений Docker-контейнера бэкенда и проверка конфигурации переменных окружения в тестах.

### NFR-002: Лимит потребления видеопамяти (VRAM)
*   **Суть:** Конвейер агентов должен стабильно работать на одной пользовательской видеокарте без переполнения памяти.
*   **Метрика / Порог:** Пиковое потребление видеопамяти ≤ 12 ГБ VRAM при использовании модели `qwen2.5:14b` (квантование 4-bit). В режиме ожидания (Idle) после таймаута выгрузки = 0 МБ VRAM.
*   **Условия:** Последовательное выполнение всех 4 шагов конвейера на эталонном запросе.
*   **Метод проверки:** Мониторинг метрик утилиты `nvidia-smi` во время выполнения сквозного сценария.

### NFR-003: Защита GPU от параллельной перегрузки
*   **Суть:** Бэкенд должен ограничивать одновременный запуск тяжелых ИИ-пайплайнов при поступлении нескольких запросов.
*   **Метрика / Порог:** Количество конкурентно выполняемых задач инференса LLM строго ≤ 1 (очередь FIFO).
*   **Условия:** Одновременная отправка 5 запросов на подбор в API `POST /api/v1/sessions`.
*   **Метод проверки:** Интеграционный тест в `pytest`, проверяющий последовательное переключение статусов задач (`PENDING` ➔ `PROCESSING` ➔ `COMPLETED`) в PostgreSQL.

### NFR-004: Точность фильтрации форумного спама и запрещенных источников
*   **Суть:** Система должна отсеивать спам-сообщения со ссылками и запрещенные площадки до этапа анализа нейросетью.
*   **Метрика / Порог:** Процент отсева постов с реферальными ссылками/спамом и ссылок на черный список (`youtube.com`) = 100%.
*   **Условия:** Прогон детерминированного фильтра на контрольном наборе из 30 фрагментов форумных веток (15 чистых обсуждений + 15 постов со спам-ссылками).
*   **Метод проверки:** Автоматизированные unit-тесты в `pytest`.

### NFR-005: Точность нормализации комплектаций (SKU Matching)
*   **Суть:** Система обязана отсекать нецелевые аксессуары и корректно разделять модификации памяти устройств.
*   **Метрика / Порог:** Отсев аксессуаров и уцененных товаров дешевле 60% бюджета = 100%. Точность извлечения конфигурации `RAM/ROM` на валидных карточках смартфонов ≥ 95%.
*   **Условия:** Обработка контрольного датасета из 50 сырых заголовков товарных карточек с маркетплейсов.
*   **Метод проверки:** Параметризованные тесты в `pytest` со сверкой выходного JSON с эталонной разметкой.

### NFR-006: Отказоустойчивость при сбоях внешних площадок и сети
*   **Суть:** Недоступность отдельного форума, блокировка запроса магазином (HTTP 403/429) или таймаут поисковика не должны приводить к падению бэкенда.
*   **Метрика / Порог:** Аварийное завершение (crash) процесса FastAPI = 0 случаев. Переход на резервные сниппеты или корректное завершение сессии со статусом `FAILED` и записью причины в БД = 100% случаев.
*   **Условия:** Искусственная эмуляция сетевых ошибок и HTTP 403/429 через библиотеку `respx`.
*   **Метод проверки:** Интеграционные негативные тесты в `pytest`.

### NFR-007: Наблюдаемость и отзывчивость интерфейса
*   **Суть:** Пользователь должен получать мгновенную обратную связь о состоянии длительной фоновой задачи.
*   **Метрика / Порог:** Время ответа API на создание сессии `POST /api/v1/sessions` ≤ 200 мс. Задержка обновления статуса текущего шага конвейера в БД ≤ 100 мс.
*   **Условия:** Локальное окружение Docker Compose при работе фонового воркера.
*   **Метод проверки:** Замеры времени отклика эндпоинтов в интеграционных тестах.

### NFR-008: Качество и валидность итоговой аналитической справки
*   **Суть:** Выходной отчет должен содержать валидную структуру Markdown, реальные ссылки из поисковой выдачи (без галлюцинаций URL) и дисклеймер по ценам.
*   **Метрика / Порог:** Доля выдуманных нейросетью URL-адресов = 0% (все ссылки подставляются детерминированным кодом из результатов поиска).
*   **Условия:** Генерация финального отчета на эталонном запросе.
*   **Метод проверки:** Автоматическая сверка всех URL в итоговом `.md` файле со списком ссылок, полученных поисковым модулем на этапе сбора данных.
